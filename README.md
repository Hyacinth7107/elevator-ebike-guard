# ElevatorGuard 🛗⚡

**电动车进电梯智能阻车预警系统** —— 基于 YOLO11 的可解释检测与人机交互

> 不只输出结果，还要**说清楚为什么**：每次判定都附带完整证据链（数量 / 置信度 / 位置 / 面积 / 人车共存 / 法规依据），并允许运维人员通过阈值滑块直接干预判定标准。

## 它解决什么问题

电动自行车进入电梯轿厢引发的锂电池热失控事故频发，《高层民用建筑消防安全管理规定》（应急管理部令第5号）第三十七条明令禁止电动车进入高层建筑公共区域。人工值守成本高、易疲劳漏检——本系统对电梯监控画面做**实时可解释检测**，输出风险等级、证据链与处置建议（语音播报 / 梯控联动 / 物业告警）。

## 核心特性

- **🔧 双模型协同**：自训 YOLO11n 检车（bicycle / ebike）+ 官方 COCO 预训练检人（person）——"人车密闭共存"作为风险升级证据
- **🔍 可解释规则引擎**：透明规则链而非黑盒打分，每次判定输出 3~6 条结构化证据（见 `app/explain.py`）
- **🎛️ 人机交互阈值**：10%~90% 判定阈值滑块即时重判；低于阈值目标以灰色虚线框显示——**主动披露不确定性**
- **📹 四种检测模式 + 拍照检测**：单张图片 · 视频抽帧（可调间隔）· 实时摄像头（getUserMedia）· 批量分析（CSV/JSON 导出）· 手机拍照检测（原生相机 capture）
- **📱 移动端双通道**：HTTP :8300（页面/检测/拍照/批量）+ HTTPS :8301（手机实时摄像头，自签名证书自动生成）
- **📦 双版部署**：FP32 ONNX（10.1MB）+ INT8 量化版（4.1MB，精度无损），按目标硬件择优
- **🧪 实测鲁棒性**：三组三阈值鲁棒性测试 + 恶劣条件（模糊/暗光/噪声）扩展实验

## 性能（全部实测）

| 指标                                | 数值                       |
| --------------------------------- | ------------------------ |
| 总体 mAP50（测试集 622 张）               | **0.899**                |
| 电动车类 mAP50                        | **0.966**                |
| 正样本检出率 @0.35                      | 99.5%（200 张，三档阈值稳定）      |
| 陌生电梯实拍（完全跨域）                      | **12/12 全检出**            |
| 恶劣条件（模糊 7×7 / 暗光 ×0.45 / 噪声 σ=25） | 检出率 100% / 100% / 98.3%  |
| 单张推理（GPU RTX 5060 / ONNX CPU）     | 42.7 ms / 54.5 ms        |
| INT8 量化                           | 体积 -60%，检出率保持 100%       |
| 官方 COCO 预训练 vs 自训（60 张电梯图）        | 45/60（语义错误） vs **60/60** |

## 快速开始

```bash
# 1. 安装依赖(建议 Python 3.10 + 虚拟环境)
pip install -r requirements.txt

# 2. 启动(仓库自带训练好的权重, 无需自行训练)
cd app
python server.py          # 或双击 start.bat (Windows)

# 3. 浏览器访问
# http://127.0.0.1:8300  →  五种输入: 单张图片 / 拍照检测 / 视频抽帧 / 实时摄像头 / 批量分析
```

> 完全本地离线运行，无任何云端依赖。`app/samples/` 内置演示图。  
> 端口可用环境变量修改：`EG_PORT=8311 python server.py`
>
> **📱 手机端访问**（需同一 WiFi）：
>
> - **HTTP** `http://电脑IP:8300`：页面浏览 / 检测 / 阈值调节 / **拍照检测**（调起手机原生相机）/ 批量分析
> - **HTTPS** `https://电脑IP:8301`：**手机实时摄像头检测**（自签名证书，首次点"高级→继续访问"）
> - 启动时终端自动打印两个地址 + 局域网 IP
>
> **🔥 防火墙**：首次使用请右键以管理员身份运行 `app/放行防火墙.bat`（一键放行 8300+8301）

## 目录结构

```
├── app/                  # 可解释预警系统(clone 即跑)
│   ├── server.py         #   零 Web 框架本地服务(Python 标准库)
│   ├── explain.py        #   ★ 可解释规则引擎(证据链+风险分级+处置建议)
│   ├── web/index.html    #   原生 HTML/CSS/JS 前端(零 CDN 依赖)
│   └── samples/          #   演示示例图
├── training/             # 训练复现脚本
│   ├── train.py          #   100 轮训练(AdamW / 640 / batch32)
│   ├── val.py            #   测试集评估
│   ├── prepare_subset.py #   8000 张子集抽样(Windows 加载瓶颈方案)
│   └── data_example.yaml #   数据集配置模板
├── experiments/          # 实验脚本(路径常量在文件顶部, 复现时自行修改)
│   ├── test_robustness.py    # 三组×三阈值鲁棒性测试
│   ├── gen_adverse.py        # 恶劣条件(模糊/暗光/噪声)扩展
│   ├── gen_int8.py           # INT8 量化(排除检测头, 精度无损)
│   ├── gen_tech_bonus.py     # ONNX测速/官方vs自训对比/阈值权衡曲线
│   └── gen_gradcam.py        # GradCAM 类别定向热力图
├── weights/              # 模型权重
│   ├── best.pt           # 自训权重(100 epochs, 5.4MB)
│   ├── best.onnx         # FP32 ONNX(10.1MB)
│   ├── best_int8.onnx    # INT8 量化版(4.1MB)
│   └── yolo11n.pt        # 官方预训练(检人用)
└── docs/                 # 实验结果图(见下)
```

## 数据增强策略(场景驱动)

依据 `runs/yolo11n_elevator_100final/args.yaml` 真实配置：**保留**亮度抖动(对应日夜光照)、水平翻转(车左右斜放入梯)、马赛克拼接(多目标/小目标)、随机擦除(乘客遮挡)；**关闭**旋转/剪切(摄像头固定安装)、上下翻转(车不会倒立)、图像混合(会模糊"人车共存"判别语义)。每项保留/关闭决策均有物理解释，并用独立恶劣条件实验闭环验证。详见 [docs/增强可视化.png](docs/增强可视化.png)。

## 数据集

训练数据：Roboflow Universe 作者 "elevator" 系列公开数据集《电梯内自行车与电动车目标检测数据集》（YOLO 格式，28,312 张真实电梯监控视角标注图；train 26,414 / valid 1,276 / test 622；类别 0=bicycle, 1=ebike）。跨域测试图来自 GitHub [ebikedetection](https://github.com/Lily-Le/ebikedetection) 项目 test_samples。
